# AGENT.md — Telegram You

Инструкция для ИИ-агента и нового разработчика. Читать целиком перед правками.

## Цель
Точная копия **Telegram для Android** в вебе: пользователь не должен заметить разницу. «Похоже» — недостаточно; сверяем размеры, цвета, иконки и поведение с оригиналом по скриншотам. Всё, что не повторяет оригинал, считается дефектом.

## Правила
1. **Копируем оригинал.** Иконки и анимации берём только из Telegram для Android (`icons/android`, `icons/tabs`; новые добавляем скриптом `tools/icons/extract-chat.py` из клона DrKLO/Telegram). Не рисуем свои, если есть оригинал.
2. **Мерим, а не прикидываем.** Сравнение: скриншот телефона и скриншот клиента в окне того же размера (ширина кадра телефона / масштаб экрана), рядом. Размеры в `css/chat.css` (блок «Measured from Telegram…») — результат такого замера; см. `docs/fidelity.md`.
3. **Нет сервера.** Всё работает в браузере. Данные пользователя не уходят никуда, кроме серверов Telegram. Сессия — в `localStorage` (`telex.session`, секрет, не логировать). `api_hash` не выводить в логи.
4. **Тексты через `t()`.** Исходный язык — русский и он же ключ: `t('Привет, {a}', { a })`, множественные числа — `tn([...3 формы...], n)`. После правок: `npm run i18n` (в `tools/i18n/translations.txt` строка `ru ‖ en ‖ es ‖ pt ‖ uk` на каждый ключ). Не оставляем ключей без перевода и неиспользуемых строк.
5. **Тема.** Только токены из `css/tokens.css`/`css/light.css` и переменные `--cx-*`. Каждый экран проверяем в светлой и тёмной теме.
6. **Тесты.** Перед коммитом `npm test` и `npm run i18n` должны быть зелёными. Новая функция — новая проверка в `tools/test/smoke.cjs` (демо-сервис `?fake=1`, живой аккаунт в тестах не используем).
7. **Расширяемость.** Новые пункты меню/хуки/события добавляем через `js/ui/ext.js`, а не прямыми вставками: встроенные функции и моды используют одни и те же точки.
8. **Не ломать.** Не удалять и не отключать тесты ради зелёного CI. Не выкладывать секреты.

## Архитектура (коротко)
```
index.html → js/ui/app.js
  ├─ js/ui/store.js      состояние S, события on/emit, форматирование времени/статусов, меню/диалоги
  ├─ js/ui/list.js       вкладка «Чаты»
  ├─ js/ui/conv.js       переписка: пузыри, композер, выбор, закреп, поиск, обои чата
  ├─ js/ui/profile.js    профиль контакта/группы/канала
  ├─ js/ui/pages.js      «Контакты», «Настройки», «Профиль»
  ├─ js/ui/panel.js      панель эмодзи
  ├─ js/ui/icons.js      оригинальные иконки (маски) + запасные inline-SVG
  ├─ js/ui/ext.js        точки расширения (меню, хуки, события)
  └─ js/ui/mods.js       загрузчик модов (ES-модули, без песочницы)
js/tg.js → js/telegram-remote.js ⇄ js/tg-worker.js → js/telegram.js (+ js/telegram-chat.js)
```
- Все вызовы Telegram идут через объект `telegram` (`S.tg`); он работает либо в Web Worker (по умолчанию), либо на странице. Методы чатов — `chat*` в `js/telegram-chat.js` (диалоги, история, отправка, правка, реакции, закрепы, пересылка, поиск, профиль, общие медиа, обои, живые обновления `startChatLive`).
- Ключи собеседников: `u123` (пользователь), `g123` (группа), `c123` (канал/супергруппа).
- Медиа: URL `media/<тип>/<ключ>/<id>` → Service Worker → страница → `telegram.fetchMedia` → байты. Новый тип медиа = ветка в `_fetchMedia` (`js/telegram.js`) + тип в `CACHEABLE`/`STREAMED` в `sw.js`.
- Демо-сервис `js/ui/fake.js` повторяет интерфейс `chat*` на сгенерированных данных.
- Ключи `localStorage` и тип сообщений SW начинаются с `telex.` — историческое имя движка, оставлено намеренно.

## Как найти точные параметры Telegram API
`node tools/tl-lookup.mjs messages.SendReaction` печатает поля метода из типов GramJS. Заметки по API — `docs/telegram-api.md`.

## Ресурсы оригинального Telegram
- `icons/android/*` — векторные (SVG, из XML-drawables) и растровые (webp/png, xxhdpi) иконки.
- `icons/tabs/*.json` — lottie-анимации нижней панели.
- `wallpapers/*` — обои с рисунком Telegram.
- Обновление/добавление: `git clone --depth 1 https://github.com/DrKLO/telegram`, затем `python3 tools/icons/extract-chat.py <путь к клону>` (добавьте имена в список `NAMES`).

## Что делать дальше
См. `docs/roadmap.md`. Порядок работы над новым экраном: скриншот оригинала → замер → вёрстка → иконки из оригинала → переводы → тест → сравнение рядом → коммит.

## Версия движка и стиль кода
Ванильный JS (ES-модули), без сборки и фреймворков; UI строится шаблонными строками; весь пользовательский текст экранируется (`escapeHtml`); обработчики — делегирование событий на контейнере (`data-a`, `data-act`). Комментарии — коротко, зачем, а не что.
