# Тестирование и проверка

Живой аккаунт Telegram в автотестах не используется, а проверять на реальном опасно. Поэтому всё проверяется на **заглушках** и на **фиктивном сервисе** (`?fake=1`, `app/static/chat/js/fake.js`).

## 1. Команды
```
npm install                 # один раз (playwright, acorn)
npx playwright install chromium    # один раз
npm run serve               # http://localhost:8765/  (добавь ?fake=1 после задачи 1.1)
npm test                    # tools/test/smoke.cjs: 5 языков × тёмная/светлая, вход, настройки, ошибки страницы
npm run i18n                # проверка, что все строки из кода переведены (падает при пропуске)
node tools/test/smoke.cjs --shots out/    # то же + скриншоты в out/
node tools/tl-lookup.mjs messages.SendMessage   # параметры метода Telegram
```
Зелёные `npm test` и `npm run i18n` — **минимум** для любой задачи.

## 2. Что проверяет `smoke.cjs`
Для каждого языка (ru, en, es, pt, uk) и каждой темы (dark, light): тема следует за устройством; открываются все страницы настроек; нет русского текста в нерусском интерфейсе; сценарий входа (телефон → код) вызывает API в правильном порядке; нет необработанных ошибок страницы (`pageerror`). Скрипт сам поднимает статический сервер и блокирует любой внешний сетевой доступ.

## 3. Как добавить сценарий для нового экрана
1. В `smoke.cjs` в цикле по языкам/темам, после блока «login flow», добавь блок:
```js
await page.evaluate(async () => {
  const { api } = await import('./js/api.js');
  api.getDialogs = async () => ({ dialogs: FIXTURE_DIALOGS, hasMore: false, nextCursor: null }); // заглушка
  window.TelegramX.setView('chats');
});
await page.waitForTimeout(300);
await scan('chats');                          // русский текст в нерусском UI = ошибка
const rows = await page.evaluate(() => document.querySelectorAll('.tx-chat-row').length);
rows > 0 && rows < 60 ? ok('chat list rendered, virtualized') : fail(`chats: ${rows} rows in DOM`);
```
2. Не обращайся к настоящему сервису: подмени `api.*` (как выше) либо используй `?fake=1`.
3. Проверяй **измеримое**: количество узлов в DOM, наличие текста, порядок вызовов API, отсутствие ошибок. Не «глазами» — глазами только скриншот сверху.

## 4. Скриншоты (обязательны для UI-задач)
`390×844`, `deviceScaleFactor 2`: тёмная и светлая темы, русский и английский. Складывать в `out/` (в `.gitignore`), в отчёте приложить. Смотри на: обрезанные тексты, налезания, пустые места, контраст в светлой теме, состояния «загрузка/пусто/ошибка».

## 5. Чек-лист для каждого нового экрана
- [ ] Работает в тёмной **и светлой** теме (нет белого текста на белом, нет чёрного на чёрном).
- [ ] Все тексты через `t()`; `npm run i18n` зелёный; в английском нет русского.
- [ ] Длинные строки (немецкие/украинские) не ломают вёрстку (проверь `uk`).
- [ ] Пустое состояние, состояние загрузки (скелетон/шиммер) и ошибка показаны человеческим текстом.
- [ ] Кнопка «Назад» (и системный жест) закрывает экран; история браузера не ломается.
- [ ] Нет утечек: список виртуализован, подписки на события снимаются при уходе с экрана.
- [ ] Доступность: `aria-label` у иконочных кнопок, фокус виден.
- [ ] Консоль браузера без ошибок и без предупреждений о ваших файлах.

## 6. Проверка производительности (минимум)
* Список из 2000 диалогов / 5000 сообщений (фикстура): `document.querySelectorAll('<строка списка>').length` ≤ 60.
* Прокрутка без «дёрганий» (смотри в DevTools Performance: нет длинных задач > 50 мс на прокрутке).
* Холодный старт с кэшем IndexedDB: первый экран < 2 с (локально).

## 7. Живой аккаунт (только с разрешения владельца)
* Только **тестовый** аккаунт или «Избранное». **Никаких** сообщений другим людям, вступлений, реакций, «прочитано» в чужих чатах.
* Строку сессии не печатать, не коммитить; в отчёте — только факты («сообщение в Избранное отправлено и отредактировано»).
* Если что-то пошло не так (FLOOD_WAIT) — остановиться и сообщить.

## 8. Релизная проверка (перед выпуском)
1. `npm test`, `npm run i18n` зелёные. 2. Версия увеличена в трёх местах (`version.js`, `sw.js`, `index.html` ×2). 3. Скриншоты ключевых экранов ×(2 темы × 2 языка). 4. Ручная проверка на телефоне: открыть сайт по LAN (`npm run serve` + адрес компьютера), войти, пройти главный сценарий. 5. Android-оболочка (если менялась) собирается (workflow). 6. Описание изменений для владельца.
