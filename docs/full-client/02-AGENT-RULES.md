# AGENT.md — правила разработки (обязательны для любого ИИ-агента)

Проект: веб-клиент Telegram **TeleX**. Статический сайт, **без бэкенда**. Клиент Telegram (MTProto по WebSocket) работает в браузере через GramJS. Читай `docs/full-client/03-ARCHITECTURE.md` перед работой.

## 0. Золотое правило
**Сначала работает, потом красиво.** Маленький, проверенный шаг лучше большого, который «должен работать». Никогда не говори «готово», пока не запустил `npm test` и не посмотрел скриншоты.

## 1. Стек и структура (не менять без разрешения)
* Чистый JS, ES-модули, без сборки. Код приложения — `app/static/`. Относительные пути (`js/…`, `css/…`), никаких `/static/…`.
* Экраны — `js/views/*.js`, компоненты — `js/components/*.js`, стили — `css/tx/*.css`, ядро — `js/core/*.js`. Новый код — **маленькими модулями**.
* Глобальный объект `window.TelegramX` (собирается в `app.js`) — это обработчики для `onclick="…"` в HTML-строках. Новый обработчик: экспортировать из модуля → добавить в `app.js` в объект `window.TelegramX`.
* Экраны регистрируются через `registerView(name, {enter, leave})` в `app.js`, навигация — `go(view, params)` из `core/nav.js`.
* Telegram-логика — **только** в `js/telegram.js` (класс сервиса). UI обращается к ней **только** через `js/api.js`. Ни один view не импортирует GramJS.

## 2. Telegram-слой: что нельзя нарушать
1. **Возвращай из `telegram.js` только простые JSON-объекты** (числа, строки, массивы, объекты). Не возвращай объекты GramJS (`Api.Message`, `BigInt`…): клиент работает в Web Worker, и всё проходит через `postMessage` (structured clone). `BigInt`/`bigInt` → в `Number`/строку.
2. Колбэки в аргументах допустимы (превращаются в `{__cb}`), но долгоживущие (подписка на обновления) нужно добавить в `PERSISTENT` в `telegram-remote.js`.
3. Новый метод класса автоматически доступен в режиме Worker (прокси). Синхронные хелперы для страницы — в объекте `local` в `telegram-remote.js`.
4. Не делай запросов «в цикле по одному». Один запрос → все данные из ответа (`users`, `chats` приходят вместе с сообщениями). Урок: `client.getMessages` + `getSender` на каждого автора давал 20 секунд задержки и FLOOD_WAIT. Бери сырые `client.invoke(new Api.messages.GetHistory(...))` и раскладывай `res.users/res.chats` сам.
5. Каждый вызов, который может упасть, должен давать **понятное пользователю сообщение** через `t()` (а не «undefined»/стектрейс).
6. Не печатай и не коммить строку сессии (`telex.session`) и `api_hash`-подобные секреты пользователя.
7. Ограничения Telegram: уважай `FLOOD_WAIT_X` (GramJS сам ждёт <60 с); не шли массовые запросы; параллельность ≤ 8.

## 3. Тексты и языки (i18n) — для КАЖДОЙ видимой строки
* Исходный язык — **русский**, ключ = русский текст: `t('Войти в Telegram')`, с подстановками `t('Скрыто каналов: {n}', {n})`, множественное число `tn(['{n} комментарий','{n} комментария','{n} комментариев'], n)`.
* **Нельзя** склеивать предложения из кусков (`t('Привет, ') + имя`): порядок слов в других языках другой. Используй `{подстановки}`.
* Даты/время/месяцы/названия стран — `Intl` и `locale()` из `js/i18n.js`, не руками.
* Добавил строку → добавь строку в `tools/i18n/translations.txt` (формат: `ru ‖ en ‖ es ‖ pt ‖ uk`) → `npm run i18n`. Если что-то не переведено, команда упадёт.
* Строки в статическом `index.html` переводятся автоматически (`translateTree`) по точному совпадению текста — их тоже добавь в таблицу.

## 4. Тема (светлая/тёмная)
* Только токены: `var(--tx-bg|surface|text|text-2|accent|separator…)`. **Никаких** `#fff`/`#000`/`rgba(...)` в новых стилях для текста и фонов поверхностей.
* Если нужен особый цвет для светлой темы — добавь правило в `css/tx/light.css` под `html[data-theme='light']`.
* Любой новый экран смотри в обеих темах (скриншоты обязательны).

## 5. Безопасность
* Любой текст из Telegram (имена, подписи, сообщения, имена файлов) в HTML — только через `escapeHtml` / `parseEmojis`; внутри `onclick="…('…')"` — через `escapeQuotes`. Не используй `innerHTML` с сырыми данными.
* Никаких сторонних скриптов/шрифтов с CDN в приложении; всё в `js/vendor/`.
* Моды/плагины (этап 8) исполняются **только в песочнице** и никогда не получают клиент или сессию (см. план).

## 6. Производительность
* Длинные списки (диалоги, история) — **виртуальный список** (рендерить только видимое). Никаких 5000 DOM-узлов.
* Тяжёлое — в Worker; на странице — только отрисовка.
* Медиа грузится только через мост `media/<тип>/…` (Service Worker + `media.js`) — не качай файлы в обход.
* Не вызывай чтение layout (`offsetHeight`, `getBoundingClientRect`) в цикле вместе с записью стилей.

## 7. Файлы, которые генерируются — не править руками
`js/vendor/gramjs.js` (сборка `npm run build:gramjs`), `css/tx/icons-android.css` и `icons/android/*` (`tools/icons/extract.py`), `js/lang/*.js` (`npm run i18n`).

## 8. Релиз (три места синхронно)
Версия: `APP_VERSION` в `js/version.js`, `SW_VERSION` в `sw.js`, `?v=` в `index.html` (две ссылки). Забыл — пользователи видят старый кэш.

## 9. Git
* Одна задача — один коммит; сообщение по-английски, повелительное наклонение, первая строка ≤ 72 символов.
* Работай в своей ветке. Не пушь в `main`, не `--force`, не переписывай историю.
* Не коммить `node_modules`, большие файлы, скриншоты (кладёшь в `out/`, он в `.gitignore`), секреты.

## 10. Лицензия
Нельзя копировать код из Telegram Web A / Web K / официальных клиентов (GPL). Можно изучать поведение и писать **свою** реализацию. Иконки Telegram уже подключены через `tools/icons`.

## 11. Как отчитываться
После задачи: (1) что сделано, (2) список изменённых файлов, (3) как проверено (команды + результат), (4) скриншоты, (5) что не сделано/сомнения. Не пиши «всё отлично» без доказательств.

## 12. Остановись и спроси
Новая зависимость; правка >5 существующих файлов; тест красный после 2 попыток; нужен живой аккаунт; сомнение в поведении оригинального Telegram; хочется сменить архитектуру.
